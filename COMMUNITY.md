# Join the Starlight Intelligence community

**One public home:** https://github.com/Starlight-Intelligence

Starlight Intelligence builds portable infrastructure for people and AI agents to work together across tools: SIP (the interoperability protocol), SIS (the sovereign reference implementation), skills, memory, voice, evaluations, and local-to-cloud systems. You can use the pieces independently.

## Choose a contribution path

| Your goal | Start |
| --- | --- |
| Learn what Starlight is | [Organization profile](profile/README.md) and [product site](https://starlightintelligence.ai) |
| Examine SIP or the SIS reference implementation | [Current source-of-truth original](https://github.com/frankxai/Starlight-Intelligence-System) pending a reviewed transfer to this organization |
| Contribute a portable skill | [Starlight Agent Skills](https://github.com/Starlight-Intelligence/starlight-agent-skills) |
| Contribute a benchmark or reproducibility fix | [Starlight Evals](https://github.com/Starlight-Intelligence/starlight-evals); honor its documented source-of-truth/freshness notices |
| Explore research or substrate experiments | [SIS historical organization](https://github.com/Starlight-Intelligence-Systems), during consolidation |
| Report a bug or security issue | The affected repository's issue template or private security advisory, respectively |

The authoritative implementation can still live under `frankxai` while mirror ownership is reconciled; **do not submit the same change to multiple mirrors**. Read the affected repository's local `AGENTS.md` and `CONTRIBUTING.md` first.

## Contribute without writing a large feature

- Verify a documented setup on a clean environment and report what succeeded and failed.
- Improve installation, quickstarts, migration docs, translation, accessibility or screenshots.
- Submit a tiny cross-harness adapter example with the exact versions tested.
- Add a reproducible benchmark with source provenance and limitations.
- Improve a Skill's `SKILL.md`, example, manifest or regression test.
- Reproduce a bug with expected versus actual behavior and a minimal test case.

Start with one focused issue, then a **draft PR**. Include the problem, evidence, tests, safety or privacy implications, source repository, and known limitations. Independent review decides admission and merge; agents can prepare work but cannot certify their own output.

## Community discussions

**Target:** organization-wide GitHub Discussions, sourced permanently from this public `.github` repository, subject to GitHub organization-owner enablement. Do not launch a temporary discussion source and later swap it: existing conversations do not transfer.

Proposed categories: Announcements, Q&A, Ideas & RFCs, Show and Tell, Integrations & Adopters, and Community Events. Until Discussions is enabled, use the right repository's issues for actionable work only.

We support respectful technical critique, attributed reuse, reproducibility, privacy, security reporting, and the right to run your own infrastructure. Adopting SIP does not require using Starlight's hosted services. No fake endorsements, artificial engagement, mass mentions or autonomous outreach.

## Community operating cadence

- **Weekly**: publish one verified release/change note and one approachable contribution opportunity, only when evidence exists.
- **Monthly**: an open build demo, office hour or maintainer AMA; invite users to demonstrate their own implementations.
- **Quarterly**: publish an evidence-linked interoperability and adoption report, including failures and maintenance burden.

Track genuine contributors, first-response time, first-PR time-to-merge, reproducible installs, independent adopters, and returning contributors—not vanity agent counts.
